# AgentMesh PRD 2.3–2.5：省用（FR-13）、去附录、去过程记录

> 来源：工作区 `D:\ZISHIKU\AI\AgentMesh` 的 `AgentMesh.md`（PRD，2.5 版 588 行 / 32,817 bytes，章节 0~14）。前序记录见 0358ccfe-7114-4e6d-9fbf-9e52ca0515d2（2.0 收敛）、3500aa04-fd3e-4895-a6d9-4e0e76af9933（2.1–2.2 附录精简与 FR-12/FR-11.6~11.8）。本文只记录 2.2 之后的增量裁决与最终结构。

## 1. 2.3：省 token（用户要求“token 消费要少，功能不要少”）

核心判断：AgentMesh 是承载 / 路由层，**自身不调用模型**，token 花在 Agent 上；因此省用是“少返工、少搬全文”，而不是砍功能。
新增 **FR-13 省用** 8 条（P0，除 FR-13.8 为 P1）：

| 编号 | 需求 | 省在哪 |
|---|---|---|
| FR-13.1 | 消息按引用传递（文件路径 / 产物编号） | 不把全文塞进消息，同一文件一链只搬一次 |
| FR-13.2 | 派活模板化 + 复用上次参数 | 长提示长度不随次数增长 |
| FR-13.3 | 提醒与看板只送摘要 | 通知只有一句摘要 + 跳转链接 |
| FR-13.4 | 交接摘要只写“做到哪、下一步” | 摘要 ≤ 200 字，可点回原文 |
| FR-13.5 | 同一任务上下文去重 | 重复内容不重复计入 |
| FR-13.6 | 失败重来只重发失败那一步 | 不整条任务重跑 |
| FR-13.7 | 适配器只回结构化结果，不回灌整屏终端输出 | 无整屏日志写入消息 |
| FR-13.8 | 任务上显示消息数 / 字符数（可选） | 只记本系统口径，不接各家计费 |

明确“不做”的省法（写进 0.2 / 决策，防止实现走形）：截断长上下文成固定字数（会截掉 Agent 需要的信息 = 减功能）、关掉交接摘要或组内共读（省一点上下文却导致返工，更贵）、摘要式转发正文（接收方理解偏差）、接各家计费口径。同时新增 NFR-9（自身不调模型、链内不重复搬运、失败重来只重跑失败步骤）、验收 F12 / F13、0.1 “用得省”行、第一波交付新增第 7 步。

## 2. 2.4：附录全部并入正文（用户：“你的改动直接改正文，不要那么多附录”）

| 项 | 2.3 | 2.4 |
|---|---|---|
| 附录 | A 决策、B 调研来源、C 交付记录（含借 C 编号长出的 C.1~C.4） | **无附录** |
| 决策 | 附录 A | 正文 15.1 关键决策 + 15.2 原有裁决处置 |
| 来源 | 附录 B | 正文 15.3 参考与来源（一张表 + 来源链接） |
| 交付记录 | 附录 C 逐笔 22 条 | 15.4 变更记录，只留版本级 6 行（1.0→2.4） |
| 删减复核 | 第 14 章 | 保留在正文 |

理由：决策与来源是 PRD 的正文依据；每次交付单开附录会让文档变成工单；改为版本级变更记录即可。行数 799 → 657。

## 3. 2.5：描述性 PRD，只留结论不留过程（用户：“PRD 不需要更新过程，只要描述性，所以不需要删减与复核记录”）

- 删除原第 14 章「删减与复核记录」：砍掉清单、回调清单、商业对照取舍、参考产品四项并进正文——与目标无关的内容留在 0.2「不做什么」边界表（8 条“不做 + 原因”），保留的能力直接体现在各 FR 条目。
- 原 15.2 的 7 条裁决处置压缩成 14.1 决策表 **D10~D15**（子代理通信范围、生命周期、记录口径、重试口径、人机协作、权限），只留结论。
- 删除 15.4 版本变更记录。
- 最终结构：0 一页看完 / 1 定位 / 2 背景 / 3 目标与非目标 / 4 用户与场景 / 5 范围 / 6 功能需求（FR-1~FR-13，13 组）/ 7 非功能需求（NFR-1~NFR-9）/ 8 交互 / 9 数据与接口 / 10 验收（A + F1~F13）/ 11 交付计划 / 12 风险 / 13 开放问题 / 14 决策与来源（14.1 D1~D15、14.2 参考与来源）。**无附录、无复核记录、无变更日志。**

## 4. 可复用的文档形态约定

- 项目只维护一份 PRD（D8）；PRD 只写“是什么、做什么、为什么这样定”，不记录“我们这轮改了什么”。
- 不设附录：决策、来源属于正文依据，放进正文章节；交付过程不进 PRD。
- “不做”的理由只保留一份，放在 0.2 边界表；不另设删减 / 复核章节，避免同一件事写两处。
- 用户反复纠正的同类问题：把“不做独立存储”简化成“不做该能力”会导致口径走样——写结论时必须同时写清载体（2.2 的共享上下文 → 任务级 FR-11.6~11.8）。

## 5. 其他约定

- 评分按用户要求不记录。
- 下一步（2.5 之后建议）：按第一波顺序推进——真实收发 → 派活 → 看板 → 失败重来 → 待我处理 → 共读交接 → 省用。
