# 标准化质量报告「未归一构成」按责任方拆桶（2026-10-21，提交 `7f81cb3`）

## 背景与目标

用户诉求：报告页不能再用一个模糊的「未归一」数字把**词表问题**和**抽取问题**混在一起 —— **责任要分开、不耦合**，各类问题能追到责任方，报告页的各类表述要能被数据反推验证。

入口实现：`java-backend/src/main/java/com/tcm/ehr/service/impl/StandardizationReportServiceImpl.java`
测试：`StandardizationUnmatchedTopTest`（含 `topExcludesInquirySentences`）
提交：`7f81cb3` fix(report): 未归一构成按责任方拆桶 —— 让抽取问题不再伪装成词表问题（3 files, +96/-10）

## 核心决策

- **只拆规则明确的三类**：问诊（与词表同源）、病程（前缀特征）、脉舌（特征词）。**模糊的一律不拆** —— 例如 `黄褐色`（属性词）**刻意留在 `dictionaryGap`**，交人工研判。原则：**宁可少拆，不可错拆**。
- **拆分只影响 top 清单与分项计数，不改变 total** —— 因此必须加「分项之和 = total」守恒断言防回归，这是防止拆桶静默丢数据的关键防线。
- **测试钉的是旧口径时，改行为必须同步改测试但保留其核心意图**：本测试原断言 `dictionaryGap = 49`（含问诊整句），行为改变后更新为按桶计数，同时新增守恒断言；「问诊整句不得进 top」的原意图完整保留。

## 「最该先补」top 清单的效果

拆桶前 top 全是抽取错位噪声，补了会造成错误映射：

```
拆前：红点多(225) 不受按(222) 中取不受按(115)     ← 舌象碎片 / 脉诊手法
拆后：难以入睡(66) 晨尿偏黄(59) 晨尿略黄(58)       ← 真候选
```

新增排除规则（同样只做**明确的**三类，关键词常量写在 `StandardizationReportServiceImpl`）：

| 规则 | 关键词 | 责任方归类 |
| --- | --- | --- |
| 脉诊手法 | `不受按` `中取` `浮取` `沉取` `应指` | 抽取（属脉象） |
| 舌象碎片 | `红点` `瘀点` `齿痕` `裂纹` | 抽取（属舌象） |
| 问诊词根扩展 | `饮水` `饮食` `精力` `体力` `控制` | 抽取 |

## 未决问题（本轮核对后交用户拍板，未实施）

1. **`normalizable` 恒 100%（denominator == numerator == 40165），且前端完全不展示** —— 属死数据。可能修法是按同一套桶判据把抽取缺陷从分母排除，并决定是否前端展示；待用户在「继续加规则细分 / 报告只报事实 / 折中」三案中选择。
2. **`fragment` 桶判据只看长度（`len<=2`）不语义** —— `咽喉`(40)、`有梦`(51)、`郁热`(39) 这类真症状被算进「碎片」桶。
3. **`dictionaryGap` 桶里仍有 `按之不痛`(40) 等否定式腹诊体征与脉象描述**（`右小紧左乏力` 44 / `右较左有力` 43）。
4. **`misrouted` 语义可能被稀释** —— 新加的脉诊手法标记与原定义「脉/舌要素进症状」混在一起，可能需再拆一桶。

## 对报告页职责的根本质疑（保持待决）

报告页的职责是**展示统计结果**，而不是**判断哪些词该补**。规则永远无法穷尽（`咽喉` 是症状还是部位？`郁热` 是证候还是属性？），每加一条规则都可能引入新误判。候选定位：**(A)** 继续加规则细分；**(B)** 报告只报事实 + 候选清单，不做自动责任判定；**(C)** 折中 —— 只保留规则明确的三类拆分，其余不拆。助手倾向 (C)。**此问题在本轮结束时仍未拍板。**

## 可复用经验

- 面对「一个数字混了多种责任」的报告指标：先按**责任方**拆桶，而不是急着补词表 —— 否则会把抽取缺陷当成词表缺口去补词，得到错误映射。
- 拆桶必须同时给出**守恒校验**（分项之和 == total），否则拆桶本身就是新的失真来源。
- 排除规则的门槛是「**规则是否明确**」而非「是否看起来是噪声」：规则不明确的一律留在原桶交人工，这是可维护性的底线。
