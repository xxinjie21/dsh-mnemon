# 术语标准化报告图表：未归一词过滤、百分比真实性、显示遮挡修复（2026-10-25）

对应提交：`a0db6da`（未归一高频词过滤 + 需研判标注）、`2cfe300`（归一率保留 1 位小数）、`52668e7`（图表显示不全）。均未推送，累计待推送 17 个 commit。

## 1. 未归一 TOP-N 的修饰词过滤（只影响展示，不改统计口径）

- 问题：报告右图「未归一实体 TOP10」里挤满描述性短语（晨尿偏黄 59、晨尿略黄 58、右较左有力 43、晨尿淡黄 41、按之不痛 40），无法直接用于补词表。
- 实现：`StandardizationReportService` 中新增 `QUALIFIER_CHARS = {'偏','略','较','尚','欠'}` 与 `looksLikeStandardTerm(String)`；`s.length() < 4` 直接放行（2~3 字的正经词不受影响），命中修饰字的词返回 false。
- **只在 `gapCount` 装入 `top` 列表时过滤**，`dictionaryGap` 计数保持真实值（62,434）不变 —— 图形清单可以筛，数字不能筛。
- 效果：清掉 3~4 条（晨尿偏黄/略黄、右较左有力等），剩余仍有噪声：黄褐色（颜色属性）、咽后壁 / 咽后壁淋巴滤泡（解剖部位）、右小紧左乏力（脉象描述）、外感风寒（实为病因/证候，跨类）、晨尿淡黄（「淡」不在词表内）、按之不痛（否定式）、心里烦得（抽取错位）。

## 2. 为什么到此为止（用户选 A 方案）

- 继续加规则（方位词左/右/寸/关/尺、含「色」、含「不」、跨类词典查重）技术上可行，但中医描述性短语没有穷举完的一天，每加一条规则就多一处误伤面；而 `dictionaryGap` 数字本身始终准确，图表只是展示清单。
- 决策：停止加规则，改为**如实标注边界**。这类「投入无底洞 + 数字已准」的情形，数字准确 + 明确声明边界 > 清单逐条正确。
- 前端文案（`web/src/components/StandardizationCharts.vue` 与 Dashboard 折叠区说明同步改）：标题「未归一实体 TOP10」→「未归一高频词」，副标题追加「· 需研判」，底部加警告：「右侧高频词仅供参考，不可直接批量录入词典：里面混有描述性短语（如「晨尿偏黄」）、解剖部位（如「咽后壁」）、跨类术语（如「外感风寒」其实是病因/证候）以及抽取错位产生的词。判断某个词能否登记为标准词，需要医学专业判断，机器过滤无法穷举。」

## 3. 归一率被四舍五入成 100%（事实层面的错误陈述）

- 根因：`StandardizationCharts.vue` 有 4 处 `Math.round(rate * 100)`，中药真实 99.7%（377025/378158）显示为「100%」，症状 56.6% 显示为 57%，且 `data: rows.map(r => Math.round(r.rate*100))` 让 99.7% 的柱子画满整格。
- 修复：新增 `const fmtRate = (rate) => \`${(rate * 100).toFixed(1)}%\```，替换 3 处文案格式化（tooltip、右图类目轴标签、工具栏说明）与数据标签；条长改为 `Number((r.rate * 100).toFixed(1))`。
- 修后实测：中药 99.7、病因 100.0（26666/26666，唯一真正满分）、脉象 96.9、舌象 94.8、证候 90.9、疾病 93.3、方剂 90.3、症状 56.6。
- 复查：全库 grep 仅此一处取整；`Dashboard` 的 `symRate` / `worstField` 本来就用 `Math.round(x*1000)/10`（1 位小数），正确，未动。
- 通用教训：任何展示给业务方的比率都不要用整数取整，接近 100 时会变成虚假满分；条形几何数据也要用同一精度，否则数值与图形互相矛盾。改完要等报告缓存（Redis statsCache，`REPORT_TTL = 180s`）过期或重启后清缓存再验证 —— 重启应用不会清 Redis。

## 4. 图表显示不全（被遮挡）

四处遮挡，一次修完（`CHART_BASE.grid` 与 CSS 同步）：

1. 底部 x 轴名「归一率（%）」被裁：轴下方实需 ≈ 63px（axisLabel ≈20 + `nameGap` 30 + 轴名文字 13），而 `grid.bottom` 只有 40，差 23px。
2. 左图 100% 柱的数据标签贴边：`xAxis.max` 100 → 110（刻度仍只到 100）。
3. 右图最高柱标签贴边：`max: (v) => Math.ceil(v.max * 1.15)`，动态留 15%。
4. 右边距不足：`grid.right` 40 → 56。

最终取值：`grid: { left: 104, right: 56, top: 10, bottom: 72, containLabel: false }`；容器 `.sc-chart` / `.sc-skel` / `.sc-fail` 高度 260 → 320px，窄视口（≤1100px）断点 220 → 280px。绘图区 = 320-10-72 = 238px，比原来 210px 更高。

**为什么不改用 `containLabel: true`**：`containLabel` 会按左图 y 轴标签宽度自动调整绘图区起点，破坏代码里 A3 硬约束「两图 x=0 起点完全对齐」，因此保留固定像素计算 `grid.left = 104`。
