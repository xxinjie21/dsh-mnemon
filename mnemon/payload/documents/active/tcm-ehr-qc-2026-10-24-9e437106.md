# tcm-ehr-qc 非主线功能评估与需求评审清单（2026-10-24）

只读需求评审结论：以「导入 → 抽取 → 归一 → 质控 → 清洗 → 导出」为唯一主线，逐项盘点 Controller / 前端路由 / 组件调用链，标注主线必备与附加功能。**未修改任何代码，处置决定待用户拍板。**

关联文档：`eaa00c66-9d76-425b-b317-8e36f63fd1fd`（完整验收评审与 P0/P1/P2 整改清单）。

## 一、主线定义与核心（不能动）

主线链路：导入 → 结构化抽取 → 术语归一 → 质控打分 → 清洗 → 导出（目标处理 34154 份病历）。

| 功能 | 位置 |
|---|---|
| 病历导入 | `RecordController`(9 端点) + `frontend/src/views/Records.vue` |
| 结构化抽取 | `NlpController`(10) + `NlpExtract.vue` + `components/NlpBatchPanel.vue` |
| 术语归一 | 抽取链路内 + `Dictionary.vue` |
| 质控打分 | `QcController`(12) + `Qc.vue` + `QcRulesDialog.vue` |
| 清洗与导出 | `GovernanceController`(9) + `Governance.vue` |
| 标准化质量报告 | `StatsController`(7) + `StandardizationReport.vue` |
| 登录鉴权 | `AuthController` + JwtInterceptor |
| 组织数据隔离 | `org_id` 字段 + RecordFilter（安全底线，不可裁） |

## 二、判定为「可直接下线」的候选（非主线，使用面极窄）

1. **词典提案审核（DictProposal 全链路）**
   - 位置：`DictProposalService/Impl`、`DictionaryController` 三端点(308/347/408)、`DictProposalDTOs`、3 个 VO、`dict_proposal` 表、`components/DictionaryProposalReview.vue`(~400 行)、`DictionaryMine.vue:394` 提交入口。
   - 成本：约 1500 行 + 6 类 + 1 表。
   - 理由：实际补词走「豆包生成 JSON → `DictionaryImport.vue` 直接导入」，提案审核是一条并行、未启用的通道。
2. **词典归档版本与回滚**
   - 位置：`DictArchiveService/Impl`、`GET /dictionary/archives`、`dict_archive_version`/`dict_archive_term` 两表。
   - 成本：约 800 行 + 2 表，且与提案功能耦合。
   - 理由：词典源在 Git（`dictionaries/*.json`）已有版本管理，DB 再存一份属重复；回滚场景 4 个月未出现。
3. **多组织生命周期管理**
   - 位置：`OrgController` 17 端点 + `Groups.vue` + `MyGroup.vue` + `organizations`/`organization_members`。
   - 建议仅裁生命周期 5 端点（archive / reassign-owner / stop / activate / transfer-owner），保留组织创建、成员管理、org_id 隔离。理由：当前仅 1 个组织 `grp-default-2026`，多组织从未真实使用。

## 三、判定为「可选保留」的功能

| 功能 | 位置 | 估量 | 判断 |
|---|---|---|---|
| AI 智能解读 | `AiController`(4) + AiService + LlmClient + `LlmConfigStore` + `LlmController`(3) + `AiInterpretCard.vue`（病历详情右栏）+ `LlmConfigDialog.vue`（顶栏）| ~2000 行 | 质控结论由规则引擎产出，AI 只换说法，不影响合格判定，但引入外部 LLM Key/费用依赖 |
| 日志审计 | `LogController`(4) + LogService + `AuditLog.vue` + OperationLogger | ~600 行 | 合规追溯需要，建议保留 |
| 人工复核工作台 | `ReviewController`(3) + ReviewService/ReviewWriteService + `Review.vue` + `review_tasks` | ~1200 行 | 现有 1838 条待复核，真实在用；若裁掉这批病历永久卡在待复核 |
| 单条 NLP 抽取试算 | `NlpExtract.vue` 单条页签 + `POST /nlp/extract` | ~300 行 | 调试工具，对维护词典与规则有实际价值 |

「可直接下线」合计约 3500 行 + 5 张表，约占后端总量 25%。

## 四、证据边界与风险提醒

- 判断基于**代码静态分析**（前端入口、调用链、表存在性）；评审时 MySQL 未运行（`ERROR 2003`），**无实时表行数/调用量证据**，需启动数据库补证后再定案。
- 安全底线：多组织即使只剩一个组织，`org_id` 数据隔离与 fail-closed 过滤不可动，只可裁生命周期管理端点。
- 下线 ≠ 删除：AI 解读若用于演示汇报，裁掉影响产品观感；复核工作台裁掉会导致积压病历无法导出。
