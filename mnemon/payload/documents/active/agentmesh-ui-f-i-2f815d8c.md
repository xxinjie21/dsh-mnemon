# AgentMesh UI 通俗用语规范与窗口嵌入可行性（附录 F–I）

> 来源：工作区 D:\ZISHIKU\AI\AgentMesh 的 `AgentMesh.md` 附录 F–I（原型文件 `ui/index.html`、`ui/app.js`、`ui/styles.css`）。项目只维护 `AgentMesh.md` 一份记录；本文是从中提炼的可复用 UI 规范与可行性结论。
> 关联文档：一期设计定稿 `d373d32b-0b73-4671-8066-ccf944a194b2`。

## 1. 用户提出的核心要求（原话要点）

- "项目的使用要方便用户，不需要设置许多晦涩难懂的词语。"
- "派生 CLI 子代理里面的配置描述也不需要设置许多晦涩难懂的词语。"（连续追问两轮，说明只改表单标签不够）
- 结论：界面文案属于体验需求，应作为 PRD 的 FR-6（体验要求）中的固定条款。

## 2. 术语 → 通俗用语对照

| 原（内部术语） | 现（界面用语） |
|---|---|
| 节点 | 成员 |
| Group 画布 / Spawn 树 | 小组画布 / 子代理树 |
| 派生 / Spawn | 新建子代理 |
| spawn_scope parent / children / tree | 谁能跟它通信：只有创建它的那个（汇报用）/ 它和它创建的下级（推荐）/ 整棵树都能找它（消息会多） |
| depth | 第 2 层 / 最多开几层子代理 |
| trace / tr-9f21 | 记录（并给出人话名，如"登录页改造"） |
| send / request / reply | 发送 / 提问 / 回复 |
| delivered / acked / failed | 已送达 / 对方确认 / 没送到 |
| answered / waiting | 已回复 / 等回复 |
| p2p | 私聊 |
| cli_agent / gui_app | 命令行代理 / 桌面应用 |
| online / busy | 在线 / 忙 |
| Herdr 已连接 | 终端正常 |
| agentmesh_request · cor_7f2a | "问 workbuddy-1：帮我改下 hover · 编号 7f2a" |
| 侧栏 tab | 记录 / 私聊 / 应用窗口 / 送达情况 |

原则：状态、模式、范围三类映射集中维护成常量表（`SCOPE_CN`、`TRACE_CN` 等），避免新文案把内部词漏回界面；技术名词（MCP、未接入）只作为徽标，不进按钮。

## 3. 新建子代理弹窗（配置描述）的写法

问题根因（第二轮才定位）：弹窗里原本只有 3 个下拉框，**模板自身的参数根本没有呈现**，用户说的"配置描述"指这一块；先用 `sed`/本地 HTTP + no-store 排除文件与缓存因素。

改法：
1. 字段按用户思考顺序编号：**1. 用哪个工具 → 2. 由谁创建 → 3. 谁能跟它通信**。
2. 每个字段下方一句"选了会怎样"：工具——"OpenCode 会开一个新的命令行窗口，跑它自己的工具和配置"；创建者——"由 opencode-1 建出来，做完会向它汇报"；范围——"现在选的是…，想让它安静干活就保持默认"。
3. 进阶项折叠进「更多设置（可不填）」：最多几层子代理、多久自动关闭，并说明后果（"超过这个层数就不让再往下建"、"到点自动关掉，省得忘了开着的进程占资源"）。
4. 顶部一句 lead："选好三项就能建，默认值已经够用。"
5. 预览从 `$ 命令 · scope · depth` 改为编号步骤"将要发生的事"，结尾写明"它不会动你原有的窗口和终端"。
6. 「这个模板的配置」卡：一句结论（会创建什么 + 能不能收发消息）+ 10 行中文明细（启动命令、工作目录、环境变量、由谁创建、出现方式、做完之后、通信范围、子代理层数、自动关闭、通信能力）。
7. 模板卡改成"先看后建"：点卡片看说明与适用场景，卡上另给「新建」按钮。
8. 消息可点开详情抽屉：类型 / 从哪来 / 发去哪 / 状态 / 方式 / 属于哪组 / 时间 / 内容；内部编号放最后并标注"排查时才用"。

默认值倾向：能默认的先默认、能折叠的先折叠、剩下一律用"会发生什么"解释。

## 4. 窗口嵌入（GUI 窗口进界面）三层结论

| 层级 | 可行 | 说明 |
|---|---|---|
| 拖拽排序、逻辑嵌入 | 可行 | 标签、位置、分组在 UI 层完成即可 |
| 画面镜像嵌入（推荐） | 可行 | 桌面壳层用 GetWindowDC / PrintWindow / Windows.Graphics.Capture 取帧，喂给嵌入面板 |
| Win32 SetParent 真塞窗口 | 技术可行但不推荐 | 跨进程父子窗口把 DPI、焦点、模态、崩溃一起拖进 AgentMesh |
| 纯浏览器内嵌原生窗口 | 不可行 | Web 无法直接显示另一个原生窗口 |

原型实现：右侧「应用窗口」tab 列出 GUI 应用（外置 · 原生窗口 / 已嵌入 · 只读画面），一键嵌入/外置；嵌入后底部终端区变为嵌入画面（● ready + 外置/采集画面）；可点「采集」或直接拖入截图/录屏；GUI 节点右键菜单有「嵌入窗口 / 外置回原生窗口」；原生窗口始终保留，可随时外置回去。

必须写进 PRD 的边界：① 嵌入是"画面镜像 + 观察"，不改变应用原生窗口；② 面板内点击/键盘默认转回原生窗口，真正"在面板里操作"需另加 UI 自动化，为可选增强；③ DRM、独占全屏、硬件加速平面可能捕获不到；④ 按需捕获、上限 15–30 fps，不常年后台录；⑤ 嵌入不越界成"托管"，应用可随时外置。

- 每次改 `ui/app.js` 后跑 `node --check`。
