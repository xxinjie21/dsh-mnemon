# tcm-ehr-qc 抽取层噪声过滤：调查、实施与「明确不做」的取舍（2026-10-21）

本文件记录 `D:/ZISHIKU/AI/tcm-ehr-qc` 在抽取层（python-nlp）做的一轮噪声过滤改造：**哪些噪声被证明确实存在、按什么判据过滤、哪些修复被主动否决及原因**。报告侧口径（可归一率、未归一拆桶）见 `e2fe1fb9-b83e-4ac8-ac6a-61fc4bc56898`。

## 一、目标与底线

- 起点：标准化率约 **87.8%**，疾病归一率 **88.9%**。噪声实体（截断药名、化验指标混进中药、脉舌碎片混进症状）既压低指标，也让「未归一 TOP 榜」失去可操作性。
- 用户底线：**诚实真实**——只做「去掉的不是数据，而是抽取缺陷」的修复；不靠移走真实信息把指标做好看。

## 二、已证实的根因（有原文对照）

### 1. NER 截断（中药）
判据：原文中该词**后紧跟剂量**（如 `10g`）= 完整；否则是截断残片。

| 抽到的 | 原文实际 |
| --- | --- |
| `中草` | `中草药处1(7付)` |
| `焦神` | `焦神曲6g` |
| `炮附` | `炮附片10g` / `炮附子12g` |
| `炒白` | `炒白芍10g` |
| `扁桃`/`玫红` | 原文无此串，属跨字段误抽 |

**判据自身踩过的坑**：最初只检查词语的**第一次出现位置**，把 `瓜蒌`(202) 等完整药名误判为截断。改为**遍历所有出现位置**后，疑似截断降到 **483 条 / 16 个词**（瓜蒌196、荆芥81、鹿角54、茯苓49、厚朴28、皂角26…）。因为更长的完整药名已被同时抽到，**丢弃残片不丢信息**。

### 2. 跨字段误抽（最严重）
`扁桃体肿大2年余` → NER 把 `扁桃`(200 次) / `扁桃体`(88 次) 放进**中药**。同类还有淋巴、甲状腺结节、脂肪肝、肝内中强回（人体部位/检查所见），以及 胡萝卜/苹果/花菜/空心菜（食物）。

### 3. 化验指标混进中药
`血沉`、`总胆红`、`血常规`、`血清肌酐`、`潜血`、`间胆`、`糖化血红蛋`、`空腹血糖`…约 110 条。仅加 `胆红素` 覆盖不了截断变体，需按词根/变体列黑名单。

### 4. 症状桶的形态噪声
- 脉舌碎片（`不受按`/`中取不受按`/`红点多`）**968 条**
- 病程诱因（`活动后缓解`/`遇劳加重`）**1210 条**
- 方剂残片（`中草药`/`太阴`/`阳明`）约 **40 条**

三项的**导出替换损失实测均为 0**（即这些实体没有任何一条产生过导出件替换），故可安全丢弃。

## 三、已实施的过滤（`python-nlp/nlp_filters.py`）

统一入口 `drop_noise(resp, full_text)`，按字段累加丢弃计数便于对账：

- `is_plausible_herb()`：中药黑名单 —— 化验指标及其截断变体 + 人体部位/检查所见 + 食物 + 截断残片丢弃（保留 `姜皮`/`瓜蒌`/`蛇胆陈皮`/`木香顺气丸` 等真药名）。
- `_is_noisy_symptom()`：脉舌碎片 + 病程诱因。
- 方剂残片黑名单（`中草药`/`中草`/`中草药处`/`太阴`/`阳明`）。
- 归位（非删除）：`nlp_rules.py` 的 `_reroute_inquiry` / `_reroute_pulse_tongue` 把命中间诊锚的整句从 symptoms 挪进 `inquiry`（不归一、不计分，但保留在 structured_data 里可查）。

验证方式与结果：
- 28 个噪声词全部拒绝；19 个真药名全部保留（`蛇胆陈皮` 未被"胆红"误伤，`岷当归`/`制龟甲`/`焦山楂` 保留）。
- 单条端到端实证：`…扁桃体肿大2年余，血常规示白细胞偏高，平素喜食苹果…岷当归10g,炒白芍12g,焦神曲6g,瓜蒌10g` → 中药 `['当归','白芍','神曲','瓜蒌']`（零残片、零黑名单项），`扁桃体肿大` 正确落在症状。
- 测试：`test_ner_chunking`、`test_noise_filter` 通过；`test_batch20_rules` 仍有 1 项**存量**失败（`舌象 边有齿痕 有损匹配 齿痕舌`），非本轮引入。

提交：`c204963`（4 项过滤）、`d9891a6`（报告侧各桶补 TOP15 词清单，纯增量、非改页面）、`4f91900`（黑名单补全）。

## 四、明确「不做」的三项（重要，防止后人重复踩坑）

| 项 | 规模 | 不做的理由 |
| --- | --- | --- |
| 疾病跨字段错位（`风湿`/`发热`/`脾虚` 等落进 diseases） | ~1068 条 | 词典核对显示这 10 个词**都不是疾病标准词**，但在其他字段有归属。移走后疾病归一率 88.9%→91.7%，**只是粉饰指标**；这些词反映「诊断栏确实这么写」，移走即丢信息。补进疾病词典同样错（`风湿` 是病因，病名应为「风湿痹病」）。按「诚实真实」保留未归一。 |
| 问诊整句（`平素…`/`喜食…`/`怕冷…`） | 919 条 / 519 词 | 池中混着**真症状**：`平素小便偏黄`(12)、`平素胸口痘疹`(5)、`怕冷又怕热`(6)。泛化加锚词会误移真症状；只加 `喜食` 类仅多移 85 条，**收益小、风险大**。 |
| 症状长尾补词 | 64796 条 | TOP200 仅覆盖 8.5%（49377 个不同词），补词无效。 |

另有一项**必须保留**的：症状桶里 9843 条问诊整句不移动，因为移走会损失 **7830 次导出替换**（如 `面黄→面色萎黄`）。`re-route` 锚词表因此在 2026-10-20 被收紧，只保留「移走零替换损失」的锚词。**为指标牺牲数据价值是方向错误。**

## 五、运维流程要点（本轮实测踩过）

1. **重启 python-nlp**：必须确认真实 PID 与 `8001` 监听，并核对新进程加载了模型（启动约 6–14 秒）。`health` 在 3 秒就返回 ok 往往说明**旧进程还在**。
2. **重抽前必须取消残留 RUNNING 任务**：任务列表接口可能返回空，但 DB 里仍有 RUNNING，提交会被 400 `已有解析任务在排队或运行中` 拒绝 —— 需**直接查库**定位。
3. 用旧代码启动的任务若跨越代码重启，**结果是新旧混合、不可信**，一律取消重跑。
4. Java 侧 class 改动（如新增 VO 字段）需**重启 8080** 才生效；python 改动只需重启 python 服务。
5. 长任务（34182 条全量重抽约 1 小时）跑完后再验证：重启后端 → 对比 87.8% 基线 → 重跑质控 → 导出验证。

## 六、复用结论

- 「判据要遍历全文本所有出现位置」——只检查首次出现会产生系统性误判。
- 「丢弃前先验证替换损失」——`导出替换损失 = 0` 是判断"这段是噪声还是数据"的客观标尺，比语义直觉可靠。
- 「指标改善 ≠ 数据改善」——能被移走的真实信息不该移走；宁可留未归一，也不粉饰。
