# AgentMesh PRD 2.1–2.2 后续裁决

> 来源：工作区 `D:\ZISHIKU\AI\AgentMesh` 的 `AgentMesh.md`（PRD，2.2 版约 729 行 / 39 KB）。前序记录见文档 0358ccfe-7114-4e6d-9fbf-9e52ca0515d2（2.0 收敛）、605ea0f0-be14-4bef-be49-82b653c9a8ef（1.1 补强层）、d373d32b-0b73-4671-8066-ccf944a194b2（一期设计定稿）。本文只记录 2.0 之后的增量裁决，不复制 PRD 全文。

## 1. 共同口径（来自 2.0）

唯一目标：让用户自定义多个 Agent 与应用之间的通讯，系统只承载与路由。收敛原则：每一行需求都必须是“不做它，用户就退回单干”的能力，表外一律不做；删减只按条目名判断是错的，要按用户流程（派活 → 互相找 → 看进度 → 失败重来 → 换人接手）逐步复核。评分按用户要求不记录。

## 3. 2.1：商业产品对照，只补 FR-12「待我处理」

对标来源：multica Inbox（https://multica.ai/docs/ 、`multica-ai/multica` 的 `apps/docs/content/docs/inbox.mdx`）、GitHub Copilot Mission Control（github.blog 2025-10-28 变更日志、cloud agent 管理文档）、n8n 执行列表（https://docs.n8n.io/build/understand-workflows/understand-executions/view-all-executions/ ，可按 Failed / Running / Success / Waiting 过滤、失败可重跑）、Orca（多 Agent 各自 git worktree）。herdr.dev 概念页读取超时，未纳入结论。

真正的缺口只有一条：**Agent 卡住等回复，用户不知道**。于是新增 FR-12「待我处理」（6 条，P0）：12.1 只收需要我动手的事（派给我的 / 卡住等我回答 / 任务失败）；12.2 同一件事多次变化合并成一条；12.3 自己的动作不通知自己；12.4 任务实时进展（点开看在做什么）；12.5 提醒设置（全部 / 只看失败 / 只看找我 / 不提醒）；12.6 已读 / 归档不影响任务。配套：0.1 增“不被卡住”一行、验收增 F9 / F10、第一波增第 5 步、数据增 `Notice` 实体（notice_id、task_id、kind、read、archived、created_at）。

明确不做：成本与耗时统计（需接各家计费口径）、多人协作 / 权限角色、移动端、自动重试策略、定时派活。第二波只记名字：再次派活、搜索、按目录分组。

> 裁决口径：10 条候选只留 3 条，每条都能在 0.1 目标映射表找到位置；不做的也写进 0.2 / 第 14 章，防文档再膨胀。功能需求从 11 组到 12 组。

## 4. 2.2：共享上下文“不做独立模块”≠“不做”

用户追问“共享上下文不做吗”暴露了表述走样：0.2 与 14.1 只写“已改为交接摘要”，读起来像砍功能。正确结论是**换载体、不砍能力**——共享上下文的价值是“换人接手不用复述”，由任务承载最自然；另建共享区会成为第二份事实源。

| 载体 | 保留 | 说明 |
|---|---|---|
| 独立共享区 / SharedContextEntry 实体 | 不做 | 与消息记录重复 |
| 任务级交接摘要（FR-11.6） | 做 | 现在做到哪、下一步是谁 |
| 组内共读消息史与产物（FR-11.7） | 做 | 同组成员只读看全过程，不改写各自会话 |
| 摘要可点回原始消息或产物（FR-11.8） | 做 | 摘要不发明事实，能追到出处 |

同步改动：0.1 增“能接手”（FR-11.6 ~ FR-11.8）；0.2 改为“不做独立存储；在任务上承接”；FR-11 从 6 条扩到 8 条；5.1 范围、8.4 交互补共读与点回；验收增 F11；第一波增第 6 步“共读与交接”；14.1 / 14.2 口径统一为“换载体，不砍能力”；Task 实体含 `handoff_summary`。

> 可复用教训：写“不做”时要写清**不做的是哪种形态**（独立存储 / 独立模块），否则等于宣称砍掉能力，用户会按字面理解。
