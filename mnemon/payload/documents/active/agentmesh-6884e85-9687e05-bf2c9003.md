# AgentMesh 原型：会话↔泳道双向定位、侧栏拖拽收起与过渡（6884e85 / 9687e05）

> 工作区 `D:\ZISHIKU\AI\AgentMesh`。2026-10-30 同一会话的两个前端增量：先做「聊天消息 ↔ 泳道节点」双向关联，再按用户要求把侧栏「拖到阈值即收起」并加过渡。
> 全部改动都在原型本体与桥接层（`prototype/prototype-bridge.js`），未复制页面、未换版式。相关文档：原型接后端与桥接映射见 `657ebab7-c6e8-46eb-a5e8-72c38c2890a0`；会话成员持久化与真实数据优先约定见 `dae86821-277a-4e0f-9fb5-e38725023ac9`。本文只记录本轮新增的交互与实现要点。

## 1. 用户诉求

- 泳道点得到会话，会话消息也要能看出「对应哪个泳道节点」，不能靠用户自己猜（双向关联）。
- 「侧边栏的拖动到一定宽度直接收起，要做过渡变化」——拖窄不是卡在最小宽度，而是越阈值收起，且必须有过渡动画。

## 2. 会话 ↔ 泳道双向定位（`6884e85`）

- 泳道步骤/任务节点 → 会话：切到 `view=chat`、滚动到对应消息、与画布/泳道/看板同步高亮约 1.5s。
- 会话 → 泳道：消息标题旁加轻量徽标 `T01 · 任务标题`；点击徽标反向定位并四视图同步选中。
- 泳道悬停提示补充「会话消息」摘要。
- 复用已有 `am-locate-hit` 高亮动效，不新增闪烁循环；未改配色/字体/圆角/间距/三栏结构。
- 实测：徽标文本为 `T01 · 下载视频并抽出 6 张关键帧`；点步骤/任务后 `view=chat`、高亮元素 7 个；控制台无报错。

## 3. 侧栏拖拽收起（`9687e05`）

阈值与行为：

| 区域 | 阈值 | 行为 |
|---|---|---|
| 左侧会话栏 `#threadPane` / 画布侧栏 `#railPane` | < 120px | 收起（共用 `am-rail-collapsed` 状态） |
| 右侧工作台 `#swimPane` | < 220px | 关闭抽屉模式 |

实现要点（`prototype/prototype-bridge.js`，`bindResizer` 约 3272 行、`setRailCollapsed` 约 2922 行）：

- 拖动监听从「元素内 pointermove」改为全局坐标判断，鼠标离开拖拽条后仍能继续判定是否越阈值。
- 收起不再用 `display:none`，而是宽度归 0 + 透明度 + 隐藏溢出，配合 0.18s ease 过渡，恢复时从 0 平滑展开。
- 拖拽期间隐藏分隔条（拖拽结束前不留下游离拖动条）。
- `collapsedDuringDrag` 守卫：拖拽期间触发的收起不回写最小宽度偏好，避免下次加载被卡在窄值。
- 自动收起（窗口变窄）不写 `localStorage`，手动切换才持久化 `agentmesh_rail_collapsed_v1`；窗口恢复后自动展开。

## 4. 可复用经验

- 用户说「拖到一定宽度就直接收起」时，关键不是调小 min-width，而是把阈值判定与「收起状态」绑定，并让拖拽结束时不落库错误宽度。
- 动画收起的元素不能用 `display:none` 做收起，否则过渡必然丢失；用宽度/透明度归零 + `overflow:hidden`。
- 拖拽型交互要监听 window 级 pointermove/up（capture 阶段），否则鼠标移出窄元素后判定中断。
- 双向关联先做「可见标识」（消息上的 `T01` 徽标）+ 复用既有高亮动效，比新增一套闪烁/联动样式更稳且视觉一致。
- 验证用 DOM 读数而非截图观感：收起后 `width=0`、`transition=0.18s`、按钮文案变「收起左侧栏」，并检查 `view=chat`、高亮命中数与控制台报错数。
